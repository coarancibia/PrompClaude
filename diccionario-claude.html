A · Fundamentos

Claude

Fundamentos

Asistente de inteligencia artificial de Anthropic. Puede conversar, analizar información, crear contenido y, cuando dispone de herramientas, trabajar con archivos o servicios conectados.

Ejemplo PD

Pedirle que compare dos propuestas de onboarding y señale ventajas, riesgos y casos faltantes.

Modelo

Fundamentos

Es el “motor” de IA que procesa la solicitud. Distintos modelos pueden variar en capacidad, velocidad, costo y tipo de tarea.

Ejemplo PD

Elegir un modelo más potente para una auditoría compleja y uno más rápido para resumir comentarios.

No confundir: Claude es el producto; el modelo es el motor que utiliza.

Prompt

Fundamentos

La instrucción o solicitud que le entregas a Claude. Puede incluir contexto, objetivo, restricciones, fuentes y formato esperado.

Ejemplo PD

“Revisa esta pantalla sin modificarla. Evalúa jerarquía, accesibilidad y casos borde. Entrega hallazgos priorizados.”

Contexto

Fundamentos

Toda la información que Claude tiene disponible para resolver una tarea: conversación, archivos, instrucciones, resultados de herramientas y datos proporcionados.

Ejemplo PD

Incluir el objetivo del flujo, tipo de usuario y restricción de negocio antes de pedir recomendaciones.

Ventana de contexto

Fundamentos

Cantidad máxima de información que un modelo puede considerar en una sesión o solicitud. Incluye mensajes, archivos, instrucciones y resultados de herramientas.

Ejemplo PD

Si se cargan demasiados documentos irrelevantes, Claude puede gastar contexto procesando información que no aporta a la auditoría.

Token

Fundamentos

Unidad pequeña en la que el modelo divide texto y otros contenidos para procesarlos. Los tokens influyen en el uso de contexto, límites y costos de API.

Ejemplo PD

Un prompt breve consume menos tokens que pegar la documentación completa del proyecto en cada mensaje.

No equivale exactamente a una palabra: una palabra puede ocupar uno o varios tokens.

Alucinación

Fundamentos

Respuesta que parece convincente, pero contiene información inventada, incorrecta o no respaldada por las fuentes disponibles.

Ejemplo PD

Claude recomienda un token llamado color.brand.primary aunque ese token no existe en el Design System.

B · Organización

Chat o conversación

Organización

Espacio de intercambio con Claude. Los mensajes previos forman parte del contexto mientras estén disponibles en la sesión.

Ejemplo PD

Usar un chat separado para cada flujo evita mezclar decisiones de registro, suscripción y pago.

Proyecto

Organización

Espacio de trabajo autocontenido con conversaciones, instrucciones y una base de conocimiento compartida sobre un tema.

Ejemplo PD

Crear un proyecto “Jumbo Prime” con tono de voz, reglas de país y documentación del Design System.

Instrucciones del proyecto

Organización

Reglas persistentes que orientan cómo debe trabajar Claude dentro de un proyecto: rol, tono, límites y fuentes prioritarias.

Ejemplo PD

“No inventes componentes. Usa el DS entregado como única fuente de verdad y solicita aprobación antes de modificar Figma.”

Base de conocimiento

Organización

Documentos y archivos cargados en un proyecto para que Claude los consulte como contexto compartido.

Ejemplo PD

Subir la guía de tono, reglas de negocio y documentación de componentes para no repetirlas en cada chat.

Compactación

Organización

Proceso de resumir una conversación extensa para liberar espacio de contexto y continuar trabajando sin conservar cada detalle literalmente.

Ejemplo PD

Después de muchas iteraciones, Claude conserva un resumen de decisiones en lugar de todos los mensajes completos.

C · Creación y trabajo

Artifact

Creación

Contenido sustancial y autocontenido que Claude presenta en un espacio separado del chat para editar, reutilizar o compartir, como una app, documento o visualización.

Ejemplo PD

Crear un prototipo interactivo para probar la jerarquía de un dashboard.

Skill

Creación

Paquete de instrucciones reutilizables que especializa a Claude en una tarea. Normalmente incluye un archivo SKILL.md y puede contener referencias o scripts.

Ejemplo PD

Una skill que audita pantallas con el mismo checklist de UX, accesibilidad y Design System.

Prompt: pedido puntual. Skill: procedimiento reutilizable.

Agente

Creación

Sistema que persigue un objetivo, toma decisiones intermedias y utiliza herramientas dentro de límites definidos, en lugar de responder solo con texto.

Ejemplo PD

Un agente revisa el archivo, consulta el DS, detecta inconsistencias y arma un reporte priorizado.

Subagente

Creación

Agente especializado al que se delega una parte acotada de una tarea, con su propio contexto y responsabilidad.

Ejemplo PD

Un subagente revisa accesibilidad mientras otro analiza inconsistencias del Design System.

Claude Code

Creación

Entorno de trabajo de Claude orientado a código, terminal y repositorios. Puede leer, editar y validar archivos cuando tiene permisos.

Ejemplo PD

Modificar un prototipo HTML, comprobar el responsive y publicar el cambio en GitHub.

Cowork

Creación

Modo de trabajo de Claude para tareas más largas y operativas con archivos, herramientas y resultados que requieren varios pasos.

Ejemplo PD

Revisar documentos de research, agrupar hallazgos y preparar una síntesis editable.

D · Integraciones y control

Herramienta o tool

Integraciones

Capacidad concreta que Claude puede utilizar para realizar una acción, como buscar, leer un archivo, ejecutar código o consultar una app.

Ejemplo PD

Usar una herramienta de Figma para inspeccionar el nodo enlazado.

Conector

Integraciones

Integración que permite a Claude acceder a datos o ejecutar acciones en otra aplicación respetando los permisos de la persona conectada.

Ejemplo PD

Conectar GitHub para revisar un repositorio o Google Drive para consultar documentación.

Plugin

Integraciones

Paquete reutilizable que amplía lo que Claude puede hacer. Puede reunir en una sola instalación skills, agentes, comandos, hooks y conexiones MCP.

Ejemplo PD

Instalar un plugin de Design System que incluya una skill de auditoría, un agente especializado y una conexión con Figma.

Skill: enseña un procedimiento. Plugin: puede agrupar una o varias capacidades para instalarlas y compartirlas juntas.

MCP

Integraciones

Model Context Protocol: estándar abierto que permite conectar Claude con herramientas, bases de datos y servicios externos.

Ejemplo PD

Un servidor MCP de Figma expone herramientas para leer información del archivo desde Claude Code.

MCP es el protocolo; un conector es la integración disponible para usar.

Permisos

Integraciones

Reglas que determinan qué puede leer, modificar o ejecutar Claude y qué acciones necesitan confirmación.

Ejemplo PD

Permitir lectura de Figma para auditar, pero exigir aprobación antes de editar un componente.

Hook

Integraciones

Automatización que ejecuta una acción cuando ocurre un evento específico durante el trabajo de Claude Code.

Ejemplo PD

Ejecutar una validación automática después de que Claude modifique archivos del prototipo.

Sandbox

Integraciones

Entorno aislado donde Claude puede ejecutar código o manipular archivos con límites de seguridad.

Ejemplo PD

Probar un script que procesa datos de research sin darle acceso libre a todo el computador.
