01

Cómo funciona el proceso

Antes de convertirse en una skill instalable, cada propuesta recorre cinco etapas: desde la definición inicial hasta su publicación.

Propuesta → Revisión → Piloto → Validación → Publicación
01

Se documenta la idea: objetivo, problema que resuelve y flujo propuesto.

02

El equipo revisa el flujo, los inputs y los outputs antes de avanzar.

03

Se prueba con casos reales y se ajusta según los resultados.

04

Se confirma que resuelve el problema sin reemplazar el criterio humano.

05

Se empaqueta como skill instalable y se comparte con el equipo.

04

Estados del ciclo de vida

Toda skill pasa por estos estados, sin importar la etapa del proceso en la que esté. No es necesario que todos aparezcan en la card principal.

BorradorIdea inicial, aún no se documenta como propuesta formal.
En revisiónEl equipo evalúa objetivo, flujo, inputs y outputs.
En pilotoSe está probando con casos reales del equipo.
ValidadaSuperó el piloto y quedó lista para empaquetarse.
PublicadaDisponible como skill instalable para el equipo.
ObsoletaYa no se recomienda usarla; fue reemplazada o descontinuada.

Editar componentes de Figma con DS Prime

Skill de Claude Code para revisar, migrar o crear componentes en Figma utilizando correctamente el Design System Prime.

Nombre técnico editar-componente-figma-dsDesign SystemVersión 5Publicada

Esta skill no reemplaza la revisión de una Product Designer. Todo componente debe validarse visualmente antes de reemplazar o publicar un componente oficial.

01

Descripción general

Actúa como especialista en Design Systems dentro de Figma, usando el Design System Prime como única fuente de verdad para migrar componentes existentes o crear átomos, moléculas y organismos nuevos.

02

Qué permite hacer

Migrar y crear componentes, aplicar el Design System y cuidar la calidad sin modificar originales.

03

Requisitos previos

Claude Code, acceso a Figma y a las librerías del Design System Prime.

04

07

Revisa la conexión MCP antes de trabajar.
