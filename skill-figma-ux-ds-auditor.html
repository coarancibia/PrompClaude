Auditoría de experiencia y Design System en Figma

Audita un frame, sección o flujo para detectar problemas de experiencia, casuísticas faltantes, uso incorrecto del Design System, accesibilidad, responsive y handoff.

Nombre técnico figma-ux-ds-auditorAuditoría UXVersión 1.0Publicada
Esta es una skill nueva y autocontenida. El instructivo de prompts sigue separado en auditoria.html. La skill utiliza el Design System que entregue cada proyecto como fuente de verdad.
Vista explicativa
01

Qué hace la skill

Resumen+

Combina auditoría de experiencia y auditoría de construcción. Reconstruye el recorrido, detecta casuísticas faltantes y compara componentes, tokens, layout y estados con las fuentes oficiales del proyecto.

02

Qué problema resuelve

Situaciones que busca detectar+

Experiencia

  • Flujos incompletos o sin recuperación.
  • Reglas de negocio poco claras.
  • Casuísticas y estados faltantes.
  • Microcopy o CTA inconsistentes.

Design System

  • Componentes duplicados o detachados.
  • Tokens y estilos mal aplicados.
  • Variantes o propiedades incorrectas.
  • Valores locales innecesarios.

Calidad

  • Problemas responsive.
  • Barreras de accesibilidad.
  • Contenido extremo no contemplado.
  • Handoff ambiguo.
03

Cuándo utilizarla / cuándo no

Rango de uso+

Usarla para

  • Auditar un frame, sección o flujo.
  • Buscar casuísticas faltantes.
  • Revisar uso del DS.
  • Preparar una revisión o handoff.

No usarla para

  • Modificar mientras audita.
  • Certificar accesibilidad.
  • Inventar reglas o tokens.
  • Rediseñar sin alcance aprobado.
04

Inputs necesarios

Obligatorios y complementarios+

Necesarios

  • Link o nodo exacto de Figma.
  • Objetivo y usuario del flujo.
  • Dispositivo o plataforma.
  • Design System de referencia.

Cuando corresponda

  • Reglas de negocio.
  • Foco de la auditoría.
  • Restricciones técnicas.
  • Métricas o evidencia.

# Auditoría de experiencia y Design System

Trabaja solo sobre el frame, sección o flujo solicitado.

## Reglas principales

- Mantén modo lectura durante toda la auditoría.
- Separa evidencia, inferencias y preguntas abiertas.
- No inventes reglas, tokens ni componentes.
- No certifiques accesibilidad solo desde Figma.
- No mezcles auditoría y corrección.

## Flujo

1. Delimitar alcance y fuentes.
2. Reconstruir el recorrido.
3. Revisar experiencia y casuísticas.
4. Comparar construcción con el DS oficial.
5. Revisar responsive y accesibilidad.
6. Priorizar hallazgos por impacto.
7. Entregar evidencia, recomendación y confianza.

## Formato

Entrega resumen ejecutivo, tabla de hallazgos, casuísticas faltantes, pendientes de definición y próximos pasos.

Si se solicitan correcciones, pide seleccionar los hallazgos exactos y solicita aprobación antes de escribir en Figma.
La descarga contiene la versión completa del archivo y sus referencias.

Decisiones que requieren revisión humana

La skill no decide esto sola+
  • Prioridad final y alcance de corrección.
  • Reglas de negocio no documentadas.
  • Creación o modificación de tokens globales.
  • Aprobación de rediseño o publicación.
  • Certificación formal de accesibilidad.
