DS2 · Figma Wireframe Generator

Convierte el brief de DS1 en wireframes de baja fidelidad directamente en Figma, usando el Design System real de cada proyecto. No genera HTML como salida principal y no está amarrada a Prisma.

Nombre técnico ds2-figma-wireframe-generatorDesign SystemVersión 2.0En piloto
Multi-DS: la skill identifica primero qué Design System corresponde al proyecto. Puede trabajar con Prime, Puntos Cencosud, Easy, Jumbo, Paris, un DS de cliente u otro sistema definido en las instrucciones. Si no encuentra fuentes confiables, se detiene y no inventa tokens ni componentes.
01

Qué hace la skill

Ejecuta el segundo paso del Diseño agéntico: toma DS1, resuelve el DS activo y construye la propuesta de wireframes dentro de Figma.

Detecta el DS

  • Lee el DS declarado en el proyecto.
  • Revisa tokens, variables, estilos y componentes.
  • No usa Prisma como fallback automático.

Construye en Figma

  • Crea la página DS2 · Wireframes.
  • Genera happy path, estados y flowchart.
  • Usa Auto Layout e instancias reales del DS.

Documenta gaps

  • Component Gap.
  • Token Gap.
  • Pattern Gap.
  • Decisiones que requieren revisión humana.
02

Qué problema resuelve

Evita que DS2 termine como un HTML separado del trabajo real de diseño o que una misma skill fuerce un Design System que no corresponde al proyecto.

Antes

DS2 generaba wireframes HTML y contenía convenciones específicas de Prisma, lo que hacía difícil reutilizarla en proyectos con otro DS.

Con esta versión

El entregable vive en Figma y la skill resuelve primero el DS activo. Reutiliza componentes y variables reales, y marca como gap todo lo que no existe.

03

Cuándo utilizarla / cuándo no

Utilízala para

  • Pasar de DS1 a wireframes en Figma.
  • Validar estructura y navegación antes de Hi-Fi.
  • Probar un flujo con el DS real del proyecto.
  • Detectar componentes o tokens faltantes.
  • Construir estados y flowchart de navegación.

No la utilices para

  • Crear la dirección visual final de DS3.
  • Modificar componentes maestros del Design System.
  • Hacer detach para forzar variantes.
  • Inventar tokens o componentes faltantes.
  • Usar Prisma si el proyecto declara otro DS.
04

Inputs necesarios y cómo activar la skill

DS2 necesita el contexto de DS1 y un destino de Figma. El Design System puede venir definido en el proyecto o indicarse manualmente.

DS1

  • design_state.json con DS1 completo.
  • Inventario P1.
  • Flujos, personas, prioridades y fricciones.

Design System

  • DS declarado en las instrucciones del proyecto, o
  • links de DS Tokens y DS Components, o
  • librerías/variables vinculadas al Figma.

Figma

  • Archivo destino.
  • Permisos de edición para construir.
  • Conector de Figma disponible.

06

Contenido base del SKILL.md

La lógica central obliga a resolver el DS antes de construir y prioriza siempre la reutilización.

Resumen operativo de ds2-figma-wireframe-generator
1. Verifica que DS1 esté completo.
2. Identifica el Design System activo del proyecto.
3. Lee tokens, variables, estilos y componentes reales.
4. No uses Prisma como fallback.
5. Crea o reutiliza la página "DS2 · Wireframes".
6. Reutiliza componente → variante → property → slot → composición.
7. No hagas detach ni modifiques componentes maestros.
8. Si algo no existe, marca COMPONENT GAP / TOKEN GAP / PATTERN GAP.
9. Construye Happy Path, Estados, Flowchart y DS Reference.
10. Actualiza design_state.json con el output de Figma.
07

Decisiones que requieren revisión humana

La skill puede construir y documentar; las decisiones que cambian el sistema siguen requiriendo criterio de diseño.

Revisar antes o durante DS2

  • Qué Design System corresponde al proyecto.
  • Qué librerías son fuente oficial.
  • Qué pantallas y estados entran en alcance.
  • Si una composición es válida o requiere un componente nuevo.

No automatizar como decisión final

  • Publicar componentes nuevos en el DS.
  • Cambiar componentes maestros compartidos.
  • Crear tokens oficiales faltantes.
  • Resolver una decisión abierta de producto sin evidencia.
08

Estado y versión

Versión actual

ds2-figma-wireframe-generator v2.0
Estado: En piloto. Debe probarse en distintos proyectos y distintos Design Systems antes de validarse.

Cambio principal

Figma reemplaza al HTML como output principal y Prisma deja de ser una dependencia fija. El DS se resuelve por proyecto.

09

Checklist de validación

Design System

  • DS activo identificado.
  • Sin tokens de otro proyecto.
  • Sin componentes inventados.
  • Gaps documentados.

Figma

  • Página DS2 creada o reutilizada.
  • Auto Layout aplicado.
  • Instancias conservan vínculo.
  • Variables y Text Styles correctos.

UX

  • Pantallas responden a DS1.
  • Estados relevantes presentes.
  • Flowchart conectado.
  • Decisiones abiertas visibles.
